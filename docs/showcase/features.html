Toolkit

Five read-only tools, one budget

List, read, search code, search docs, and semantic retrieve over a lazy TF-IDF index. Every call consumes one step of a shared budget (1–20, default 8); retries never multiply the cost.

  • Path-confinement rejects .. and absolute paths
  • ≤400 lines per read, ≤50 matches per search, 1 MB cap
  • Wrapped in retry, timeout, and output validation

Reasoning

Plan → execute → reflect

The agent declares a short plan before inspecting, revises it when a step returns nothing, and reflects on whether steps could merge. Meta-tools are free; only real inspection spends budget.

  • create_plan, replan, reflect_plan
  • Duplicate tool calls are blocked
  • Loop stops early once evidence is sufficient

Trust

Honest when the evidence isn't there

Negative answers are a feature. When a search finds nothing, Flowly reports insufficient evidence instead of inventing a subsystem that doesn't exist.

  • Confidence drops to Insufficient or Low
  • The answer names exactly which tools were tried
  • No fabricated citations, ever

Factory

Issue in, reviewed draft PR out

Label an actionable GitHub issue factory. Flowly classifies it, creates a repository-grounded plan, implements it in an isolated clone, runs the plan's repository-native checks, and sends the real diff to an independent reviewer.

  • Factory-owned factory/* branches only
  • Failed verification stops without a pull request
  • Publishes a draft; never auto-merges or auto-approves
issues.labeled.factory
classify → plan → implement
    → verify → independent review
    → draft pull request

  target: repository checked out by the workflow
  branch: factory/<issue>-<slug>
  merge:  never
  approve: never

Review

PR review that never auto-approves

A second agent reviews pull requests with file-aware limits, incremental diffs since the last review, and repository-specific memory. The model emits structured findings; a trusted publisher re-validates every one before posting.

  • Verdict is COMMENT or REQUEST_CHANGES, never APPROVE
  • Paths checked against the diff, lines clamped to hunks
  • Previous findings classified: resolved, still-present, obsolete, uncertain
trusted publisher
submit_review → publisher

  validate  schema · path in diff · line in hunk
  clamp    line numbers to valid hunks
  cap      findings at the configured limit
  post     exactly one review, never APPROVE

  inline findings + body summary,
  dropped findings still summarized (nothing silent)

Automation

Route GitHub events to agents

A dependency-light router maps GitHub events (PRs, issues, comments, reviews, workflow runs) to agent IDs with declarative routes and filters. The router only decides; the checked-in workflow wires the review and factory jobs.

  • First-match routing with AND-ed filters
  • Duplicate deliveries deduplicated
  • Malformed events ignored safely, never crash
event-router.config.json
{
  "routes": {
    "pull_request.opened": "review",
    "pull_request_review.submitted": "address-review",
    "issues.opened": "planner",
    "issues.labeled.implement": "implementation",
    "issues.labeled.factory": "factory",
    "workflow_run.completed.failure": "ci-fix"
  }
}

Evaluation

Benchmark models with or without a key

A built-in benchmark runs seven repository-assistant scenarios and scores tool success, citation accuracy, retrieval relevance, and answer completeness. Deterministic mode is key-free and CI-safe; live mode calls a real provider.

  • Keyword judge by default, optional LLM judge
  • Reports record latency, tokens, cost, and acceptance
  • Human accept/reject verdicts fold back in
