Toolkit

Five tools. One budget. Zero side effects.

Every inspection call consumes one step of a shared budget (1–20, default 8). Retries never multiply the cost — one step per logical call. Planning meta-tools are free.

🗂️
list_files

Walk the repository tree — the cheapest way to discover structure when a path is unknown.

consumes budget
📄
read_file

Read a bounded line range (≤ 400 lines) from a known file to ground claims in context.

consumes budget
🔎
search_code

Literal search over source files (≤ 50 matches) for symbols, config, and implementations.

consumes budget
📚
search_docs

Literal search over documentation files — README, AGENTS, CHANGELOG, docs/, Markdown.

consumes budget
🧠
retrieve

Semantic retrieval over a lazy TF-IDF index of source and docs, chunked at ~50-line segments. No external embeddings, no vector database.

consumes budget
🧭
create_plan · replan · reflect_plan

Declare a 3–5 step plan before inspecting, revise it when a step returns nothing, and reflect on whether steps could merge.

meta-tools — no budget

How it works

Plan, observe, act, reflect, answer.

The agent doesn't follow a hard-coded sequence. It declares a short plan, decides which tool to call, and reflects on whether it has enough evidence — or needs to dig deeper. Search results are leads, not proof; claims are only made after file reads.

1
Plan Declare 3–5 steps via create_plan — no budget spent
→
2
Observe List, read, search, or retrieve — cheapest useful call first
→
3
Reflect Enough evidence? If not, act again — or replan with new scope
→
4
Answer Lead with conclusion, cite every claim with paths and lines

Beyond the loop

A small agent, surrounded by the tools to trust it.

The core loop is the foundation. Around it live a PR reviewer, an event router, a model benchmark, a reliability layer, and a living set of architecture docs.

agent

PR review agent

Reviews pull requests with file-aware limits (30 files, 4000 diff lines), incremental reviews, and repository memory — and never auto-approves.

github/events

Event router

Maps PR, issue, comment, review, and workflow-run events to configured agents with declarative routes, filters, and duplicate-delivery dedupe.

eval/bench

Model benchmark

Seven capstone scenarios scored on tool success, citation accuracy, retrieval relevance, and completeness — deterministic in CI (keyword judge), or live with per-model providers and an optional LLM judge (--judge-model).

reliability

Retry, timeout, validate

Transient failures retry with exponential backoff and jitter; permanent errors fail fast with user-safe messages. A search→read fallback keeps answers useful.

planner

Deterministic planner

The same plan→execute→reflect contracts the model uses are exposed as pure functions — so tests prove the behaviour without a provider key.

docs

ADRs & code map

Architecture decisions live in docs/adr/; the seven-document code map lives in .planning/codebase/.

Security

Repository access is application-controlled.

The model requests file operations by name. The application validates, confines, and caps every access before the filesystem is touched.

1

Only repository-relative paths accepted

Absolute paths and .. traversal are rejected at input validation, before any filesystem call.

2

Symlink resolution checked

Canonical paths are verified against the repo root after realpath. Symlinks pointing outside the repo are blocked.

3

Output caps enforced

400 lines per read, 50 matches per search, 1 MB file limit. Directory walks skip symlinks, VCS data, dependencies, and build output.

4

Finite inspection budget

One shared 1–20 call budget across all five tools; exhaustion stops the loop and the agent answers from collected evidence.

5

Content treated as untrusted data

Repository file content is never interpreted as instructions. The model is told to ignore instructions found in files.

6

No shell, Git, or network

Flue's default filesystem and shell tools are removed. Access exists only through the five inspection tools.

Get started

Two clones, one question.

Point the agent at any local Git repository. The default target is project-oak/oak, a Rust monorepo for privacy-preserving distributed systems.

1

Clone both repositories as siblings

git clone https://github.com/jellydn/flowly.git git clone --depth 1 https://github.com/jellydn/oak.git
2

Install dependencies and set your API key

cd flowly npm install cp .env.example .env # add your OPENROUTER_API_KEY to .env
3

Ask a question

npm start -- --input '{"message":"What is the architecture of oak?"}'

Run the benchmark without an LLM key

npm run eval -- run — seven deterministic scenarios, safe for CI. Add --live --json to hit a real provider.

Route a GitHub event

npm run route-event maps a webhook payload to an agent with declarative routes — the seed of event-driven workflows.

Requires Node.js ≥ 22.19.0. Override REPOSITORY_PATH to inspect any local checkout; tune the budget with REPO_ASSISTANT_MAX_STEPS.
