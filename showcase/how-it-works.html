How it works

What using Flowly actually looks like.

This is the real, deterministic output of the bundled demo with no API key or editing. The agent runs the whole loop against a fixture repository and prints every step.

1

Point it at a repository, then index it

Flowly reads one local checkout. On first retrieve, a lazy TF-IDF index chunks source and docs into ~50-line segments, with no embeddings or vector database.

repository → index
Step 1: Repository Selection
  Repository: eval/fixtures/sample-repo

Step 2: Indexing (TF-IDF)
  Files indexed:  8
  Chunks indexed: 8
  Unique terms:   72
  Build time:     14ms
2

Ask a question

One natural-language question. The agent declares a short plan first. Planning costs no budget.

chat question
$ "Review this repository, explain its architecture,
 identify the highest-risk issue, and suggest an
 implementation plan."
3

Retrieve the relevant evidence

Semantic retrieval scores candidate chunks and returns the strongest leads. Search results are leads, not proof. The next step reads the files to confirm.

RAG retrieval
[score: 0.369] README.md:1-19 (documentation)
[score: 0.222] src/utils/notes.md:1-4 (documentation)
[score: 0.068] docs/architecture.md:1-12 (documentation)
4

Execute tools inside the budget

Each inspection call spends one step of the shared budget. The loop stops early when the evidence is sufficient. In this run, two calls were enough.

tool execution
Tools used:     retrieve → read_file
Iterations:     2
Stop reason:    sufficient evidence for architecture review
Evidence items: 3
5

Answer with citations and confidence

The answer names the exact files and lines it read. Confidence reflects what was actually retrieved, and the answer states low confidence instead of hiding it.

cited answer
Confidence: Low
Sources:    README.md:1-19, docs/architecture.md:1-12,
           AGENTS.md:1-7

  Answer:
    Based on evidence from 3 source(s) across
    documentation, here is what I found...

    - # Sample Repository (README.md:1-19)
    - # Architecture (docs/architecture.md:1-12)

    Confidence is Low because the evidence is incomplete
    (only search leads, no file reads to confirm).
6

Measure the run

The benchmark scores the same loop across seven scenarios (tool success, citation accuracy, retrieval relevance, and answer completeness) and reports the outcome.

evaluation report
Scenarios: 7  |  Passed: 7  |  Failed: 0

  Citation Accuracy:    7/7
  Retrieval Relevance:  7/7
  Tool Success:         7/7
  Answer Completeness:  7/7

  ✅ [cap-1] What is the purpose of this repository?
  ✅ [cap-2] Where is authentication implemented?
  ✅ [cap-3] What happens when a GitHub API request times out?

That's the whole loop.

Deterministic, key-free, and reproducible: run it yourself in one command.
